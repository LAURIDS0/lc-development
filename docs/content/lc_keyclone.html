LC Keyclone

Repository Download

Clone vehicle keys and door keycards with a key cloner. The player gets LC Hack's terminal and desktop with two extra commands: scan finds parked vehicles and keycard readers nearby, and connect connects to one. Then the player logs in, finds the code and uses it with su.

Installation

Install all resource dependencies

  • LC Hack 1.4.0 or newer
  • ox_lib
  • A vehicle key script (optional): qbx_vehiclekeys, qb-vehiclekeys, wasabi_carlock, qs-vehiclekeys, MrNewbVehicleKeys, jaksam's vehicles_keys or cd_garage, see Key Scripts.
  • ox_inventory (optional, for the device and the keycards)
  • OneSync, so the server knows the vehicles.

Download the resource

  • Download the latest version and unzip it as lc_keyclone.
  • Or clone the repository: git clone https://github.com/LAURIDS0/lc_keyclone.git

Start the resource

ensure ox_lib
ensure lc_hack
ensure lc_keyclone

Add the device

With ox_inventory, add the key cloner to ox_inventory/data/items.lua. consume = 0 keeps it when it's used.

['key_cloner'] = {
    label = 'Key Cloner',
    weight = 800,
    stack = false,
    consume = 0,
    server = { export = 'lc_keyclone.useCloner' },
},

Without ox_inventory, players open it with /keycloner, see command.

Add keycard readers

Vehicles work right away. Doors need a reader in the config, see Keycard Readers.

Common Issues

Problems that come up when setting up lc_keyclone, and how to solve them.

scan doesn't find a vehicle

  • Only parked vehicles are listed: nobody may sit in the driver seat.
  • Vehicles in vehicles.blacklist are never listed.
  • The vehicle must be within range (default 15.0 meters), and the server must know it (OneSync).

scan doesn't find a reader

Readers come from readers in the config. Check its coords, and that the player is within range of them.

The player got root but no keys

  • Keys are given with one of the supported key scripts. With keys = 'auto', one of them must be started; with another key script, give the keys in onCloned.
  • The server console prints [lc_keyclone] ... could not give keys when the key script fails.
  • The vehicle must still be parked and within range when the player becomes root.

The cloned keycard doesn't open the door

Add the reader's item to the door's items in ox_doorlock. LC Keyclone only gives the item; ox_doorlock decides what it opens.

/keycloner doesn't exist

The command is only added when ox_inventory isn't started. With ox_inventory, players use the key_cloner item.

Config

Everything is in config.lua in the resource folder. It is only loaded on the server. Restart the resource after changing it.

range

  • range: number
    • How far away (meters) a vehicle or reader can be found with scan, and how close it must stay to connect and to get the reward. Defaults to 15.0.

maxTargets

  • maxTargets: number
    • Most targets scan lists, closest first. Defaults to 8.

cooldown

  • cooldown: number
    • Seconds before the same vehicle or reader can be cloned again. It shows as locked meanwhile. Defaults to 900.

attempts

  • attempts: number
    • Wrong passwords and codes allowed in one session. The device closes when they run out. Defaults to 4.

desktop

  • desktop: string or false
    • The device's desktop, one of LC Hack's desktops, or false for a terminal only. Defaults to 'kali'.

item

  • item: string
    • The ox_inventory item that opens the device. Point its server.export to lc_keyclone.useCloner. Defaults to 'key_cloner'.

command

  • command: table or false
    • A command that opens the device when ox_inventory isn't started. false for none.
    • name: string
      • Defaults to 'keycloner'.
    • restricted?: string or false
      • An ace the player needs, e.g. 'group.admin'. false for everyone.

vehicles

  • vehicles: table
    • enabled: boolean
      • List parked vehicles in scan. Defaults to true.
    • keys: string or false
      • The key script that gives the keys, see Key Scripts. 'auto' uses the first supported one that is started, a resource name always uses that one, false gives no keys. Defaults to 'auto'.
    • blacklist: string[]
      • Spawn codes that can never be cloned, e.g. emergency vehicles.
vehicles = {
    enabled = true,
    keys = 'auto',
    blacklist = { 'police', 'police2', 'ambulance', 'firetruk' },
},

readers

  • readers: table[]
    • Keycard readers at doors, see Keycard Readers.
    • label: string
      • The name scan shows.
    • coords: vector3
      • Where the reader is.
    • item: string
      • The keycard item the player gets (ox_inventory).

onCloned

  • onCloned: function(source: number, kind: 'vehicle' | 'reader', target: number)
    • Called on the server for every clone, with or without a key script and ox_inventory. target is the vehicle's network id, or the reader's index in readers.

Example

onCloned = function(source, kind, target)
    if kind == 'vehicle' then
        -- Alert the owner, give XP, ...
    end
end,

Server

openCloner

Opens the key cloner for a player, e.g. from your own item, job or command.

exports.lc_keyclone:openCloner(source)
  • source: number

Return:

  • boolean - Returns false if the player is already hacking.

useCloner

The ox_inventory item export. Point the key cloner item's server.export to it; you don't call it yourself. It opens the device and keeps the item.

server = { export = 'lc_keyclone.useCloner' },

Key Scripts

A cloned vehicle gives keys with the key script your server uses. LC Keyclone works with the seven most used ones out of the box.

Supported key scripts

With vehicles.keys = 'auto' (the default), the first of these that is started is used, in this order:

Key scriptHow the keys are given (server)
qbx_vehiclekeysexports.qbx_vehiclekeys:GiveKeys(source, vehicle, true)
qs-vehiclekeysexports['qs-vehiclekeys']:GiveKeys(source, plate, true)
wasabi_carlockexports.wasabi_carlock:GiveKeys(source, plate, model)
MrNewbVehicleKeysexports.MrNewbVehicleKeys:GiveKeys(source, netId)
vehicles_keys (jaksam)exports['vehicles_keys']:giveVehicleKeysToPlayerId(source, plate, 'temporary')
cd_garageTriggerClientEvent('cd_garage:AddKeys', source, plate)
qb-vehiclekeysexports['qb-vehiclekeys']:GiveKeys(source, plate)
  • Plates are passed without the spaces GTA pads them with.
  • qb-vehiclekeys is tried last, because several other key scripts also answer to its name.
  • An error in the key script is printed in the server console; the clone still counts and onCloned is still called.

Choosing one

If more than one is started, set the one to use:

vehicles = {
    keys = 'wasabi_carlock',
},

Another key script

Set keys = false and give the keys in onCloned. It gets the vehicle's network id:

vehicles = {
    keys = false,
},

onCloned = function(source, kind, target)
    if kind ~= 'vehicle' then return end
    local vehicle = NetworkGetEntityFromNetworkId(target)
    local plate = GetVehicleNumberPlateText(vehicle)
    exports.my_keys:GiveKeys(source, plate) -- your key script's export
end,

Keycard Readers

A reader makes a door clonable: the player connects to it and gets a keycard item, and ox_doorlock lets that item open the door.

Create the keycard item

Add an item for the door to ox_inventory/data/items.lua:

['keycard_vault'] = {
    label = 'Vault Keycard',
    weight = 10,
},

Add the reader

Add it to readers in config.lua, at the reader on the wall next to the door:

readers = {
    {
        label = 'Vault Door',
        coords = vec3(255.2, 223.4, 102.4),
        item = 'keycard_vault',
    },
},

Let the keycard open the door

In ox_doorlock, add keycard_vault to the door's items. Anyone with the item can then open it, like with ox_doorlock's other item doors.

Restart and test

Restart lc_keyclone, stand near the reader and run scan on the device.

Playing

What the player does, from opening the device to the keys.

Open the device

Use the key_cloner item, or /keycloner without ox_inventory. help lists the new commands under "Tools".

Scan

scan lists parked vehicles and keycard readers nearby, closest first.

ID  TYPE     NAME                  STATUS
1   vehicle  KEY-9732              available
2   reader   Vault Door            available
3   vehicle  KEY-41C0              locked

locked targets were cloned a moment ago and can't be cloned yet.

Connect

connect 1 connects and tells the IP. Log in with ssh service@<ip>; no password is needed.

Find the code

The code is somewhere in the files: a config, a log, a file in base64 (base64 -d) or inside a binary (strings). An old code is there too, and a wrong code costs an attempt.

Become root

Run su and type the code. A vehicle gives keys, a reader gives its keycard. The device stays open for the next one.

How it Works

lc_keyclone is a hack type built on LC Hack's building blocks, like LC Phonehack.

The device

The device is an LC Hack hack with target = false, so it stays open until the player closes it, and two commands that run on the server: scan and connect.

Targets

connect adds the vehicle's key module or the reader with addMachine. Its user has no password, and its root password is the code hidden in its files. onRoot gives the keys or the keycard.

Security

Everything runs and is checked on the server; the client only shows the terminal.

  • scan reads the vehicles near the player on the server. Vehicles with a driver and blacklisted models are skipped.
  • connect checks that the target still exists, is within range and not on cooldown.
  • The code stays on the server like every password in LC Hack; every attempt is checked there.
  • The reward is given in onRoot, once per connection, and only while the target is still parked and within range.
