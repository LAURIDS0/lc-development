LC Datahack

Repository Download

Break into company networks and steal their data. Every company is a computer in the world with a network behind it: the player finds the login for the next server, hops from server to server and gets root on the file server. The player gets the company's data as an item, and the network goes offline for a while.

Features

  • A new network every time: new passwords, hidden in new places (config files, shell history, scripts, base64 notes, binaries), with a decoy.
  • 1 to 5 servers per company, each only reachable from the one before it.
  • Built on LC Hack's terminals: ox_target or [E], pausing, and optional in-world screens.
  • A USB drive to start, the data as an item, and a cooldown per company.

Installation

Install all resource dependencies

  • LC Hack 1.5.0 or newer
  • ox_lib
  • ox_inventory (optional, for the USB drive and the data item)

Download the resource

  • Download the latest version and unzip it as lc_datahack.
  • Or clone the repository: git clone https://github.com/LAURIDS0/lc_datahack.git

Start the resource

ensure ox_lib
ensure lc_hack
ensure lc_datahack

Add the items

With ox_inventory, add them to ox_inventory/data/items.lua:

['usb_drive'] = {
    label = 'USB Drive',
    weight = 20,
},

['data_usb'] = {
    label = 'Stolen Data',
    weight = 20,
    stack = false,
},

Try it

Run /datahacktest as an admin. It creates a test company where you stand; use the computer with a USB drive in your inventory.

Common Issues

Problems that come up when setting up lc_datahack, and how to solve them.

"You need a USB drive."

With ox_inventory, the player needs the item (default usb_drive). Set item = false to let everyone hack.

"The ... network is offline."

The company's data was stolen a moment ago. It is back after cooldown seconds (default 1800).

The computer doesn't show

  • Check the site's coords. Without ox_target, it is an [E] point.
  • The server console prints a site needs a name and coords for sites that are missing them.
  • LC Hack 1.5.0 or newer is required.

No data item

The item is only given when ox_inventory is started. Without it, give rewards in onStolen.

Config

Everything is in config.lua in the resource folder. It is only loaded on the server. Restart the resource after changing it.

item

  • item: string or false
    • The ox_inventory item a player needs to use a company's computer. false for none. Defaults to 'usb_drive'.

consumeItem

  • consumeItem: boolean
    • Remove one item when the data is stolen. Defaults to true.

reward

  • reward: table or false
    • The data item, with ox_inventory. Its label becomes "Company data", and its metadata has company (the site's name).
    • item: string
      • Defaults to 'data_usb'.
    • count?: number
      • Defaults to 1.

attempts

  • attempts: number
    • Wrong passwords allowed per hack. Defaults to 3.

desktop

  • desktop: string or false
    • The workstation's desktop, one of LC Hack's desktops, 'random', or false for a terminal only. A site can set its own. Defaults to 'random'.

cooldown

  • cooldown: number
    • Seconds a company's network is offline after its data was stolen. A site can set its own. Defaults to 1800.

testCommand

  • testCommand: table or false
    • A command that creates a test company where you stand. false for none.
    • name: string
      • Defaults to 'datahacktest'.
    • restricted?: string or false
      • Defaults to 'group.admin'.

sites

  • sites: Site[]
    • The companies, see Site.

onStolen

  • onStolen: function(source: number, site: string)
    • Called on the server for every theft, with or without ox_inventory. site is the site's name.

Example

onStolen = function(source, site)
    -- Alert the police, give XP, ...
    print(('%s stole the data of %s'):format(GetPlayerName(source), site))
end,

Site

Every company is an entry in sites in config.lua.

sites = {
    {
        name = 'lifeinvader',
        label = 'Lifeinvader',
        coords = vec3(-1054.2, -230.6, 44.0),
        hops = 2,
    },
},

name

  • name: string
    • Unique and lowercase. It is used in the hostnames, e.g. lifeinvader-files01.

label

  • label: string
    • The company's name, shown on the computer and the data item.

coords

  • coords: vector3
    • Where the computer is.

hops

  • hops?: number
    • Servers between the workstation and the data, including the file server: 1 to 5. More hops = a harder hack. Defaults to 2.

desktop

  • desktop?: string or false
    • This site's workstation desktop. Defaults to desktop in the config.

cooldown

  • cooldown?: number
    • This site's cooldown. Defaults to cooldown in the config.

radius

  • radius?: number
    • How close the player must be. Defaults to LC Hack's terminal radius (1.5).

screen

  • screen?: table
    • An in-world screen that shows the hack to everyone nearby, like LC Hack's screens.

Adding a Company

Find the computer

Stand at the desk or server rack where players should hack, and note your position, e.g. with /datahacktest or your coordinates tool.

Add the site

sites = {
    {
        name = 'maze',
        label = 'Maze Bank',
        coords = vec3(-75.4, -818.6, 243.4),
        hops = 4,          -- a bank: make it hard
        cooldown = 3600,
    },
},

Add a screen (optional)

A monitor on the wall that shows the hack to everyone nearby. See Screens for the fields.

Restart and test

Restart lc_datahack and use the computer with a USB drive.

Playing

What the player does, from the computer to the data.

Use the computer

With a USB drive in the inventory, use the company's computer. The workstation opens, with a welcome note on the desktop.

Find the first login

The login for the first server is somewhere on the workstation: shell history (cat ~/.bash_history), a script, a config file or a note. Notes may be in base64: base64 -d <text>. /etc/hosts shows the server's name.

Hop from server to server

ssh user@server, then look for the next login there. Each server only accepts the one before it, so the player can't skip one.

Get root on the file server

The file server has the data in /srv/data. Its root password is somewhere on it, maybe in a binary (strings). Run su with it: the data is stolen.

An old password is planted on the way. Every wrong password costs an attempt, and the hack fails when they run out.

How it Works

lc_datahack is a hack type built on createTerminal.

  • Every site is an LC Hack terminal. Its config is a company network: the workstation, the servers in a chain, and the file server as the target.
  • canUse checks the cooldown and the USB drive before a hack starts.
  • onSuccess gives the data, takes the site offline and builds a new network with new passwords.
  • Every password stays on the server, and every attempt is checked there, like in any LC Hack hack.
