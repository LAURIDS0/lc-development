LC Job Garages

Repository Download

Job garages for Qbox. Police, EMS and other jobs take out fully set up job vehicles: liveries, extras, mods, plates and starter items in the glovebox and trunk, limited by job grade. A command writes a vehicle's config for you from the vehicle you sit in.

Installation

Install all resource dependencies

  • qbx_core
  • qbx_vehiclekeys
  • ox_lib
  • ox_inventory
  • oxmysql

Download the resource

  • Download the latest version and unzip it as lc_jobgarages.
  • Or clone the repository: git clone https://github.com/LAURIDS0/lc_jobgarages.git

Start the resource

ensure ox_lib
ensure oxmysql
ensure qbx_core
ensure qbx_vehiclekeys
ensure ox_inventory
ensure lc_jobgarages

Set up your garages and vehicles

The included garages use addon vehicles (e.g. tstudio_*) that you may not have. Change them to your own, see Adding a Garage and Adding a Vehicle.

Usage

Players with the job walk into the garage zone and press E:

  • On foot: a menu lists the vehicles their grade may use. The vehicle spawns at the first free spawn point with keys, and the player is put in the driver seat.
  • In a job vehicle (as the driver): the vehicle is returned and removed.

Next steps

  • Adding a Vehicle: from a vehicle in game to a config with /creategaragecar.
  • Vehicle: every field a vehicle can have.

Common Issues

Problems that come up when setting up job garages, and how to solve them.

A garage has no vehicles in the menu

  • The folder with the vehicle files must be listed in shared_scripts in fxmanifest.lua, see Adding a Garage.
  • The garage name in the vehicle files (Config.JobVehicles['police_ls']) must match the garage's key in Config.JobGarages exactly.
  • Vehicles with access are hidden from grades outside minGrade and maxGrade.

A vehicle doesn't spawn

  • Every spawn point has a vehicle within 2.5 meters. Move them or add more spawn points.
  • The vehicle's model must be a spawn code that exists on the server (its resource must be started).

Mods, liveries or extras look wrong

Mod values are different on every addon vehicle. Generate the config with /creategaragecar on the exact vehicle instead of copying values from another one.

The glovebox or trunk is empty

  • Every item name must exist in ox_inventory. The server console prints [lc_garages] ... success=false for items that fail.
  • The inventories are found by the vehicle's plate. A vehicle without a plate gets no items.

The zones are drawn in the world

Config.Debug is true in the default config. Set it to false in config/config.lua.

Config

The configuration is split in two levels: the garages, and one folder of vehicle files per garage. Restart the resource after changing anything.

config/
    config.lua          # Debug
    jobgarages.lua      # every garage: Config.JobGarages
    police_ls/          # the vehicles of the garage "police_ls"
        tstudio_polcypher.lua
        ...
    ems_sandy/
        ...

Debug

  • Config.Debug: boolean
    • Draws the garage box zones in the world, to place them. Defaults to true; set it to false on a live server.

Load order

fxmanifest.lua loads the files in this order, and it matters: config.lua creates the tables, the vehicle folders fill Config.JobVehicles, and jobgarages.lua fills Config.JobGarages.

shared_scripts {
    '@ox_lib/init.lua',
    'config/config.lua',
    'config/police_ls/*.lua',
    'config/ems_sandy/*.lua',
    -- one line per garage folder
    'config/jobgarages.lua'
}

A new garage folder must be added to shared_scripts, or its vehicles are never loaded.

Garage

Every garage is an entry in Config.JobGarages in config/jobgarages.lua. It says where the garage is, who can use it and where vehicles spawn; the vehicles themselves are in the garage's vehicle files.

Config.JobGarages = {
    ['police_ls'] = {
        label = 'Los Santos Police Garage',
        jobs = {
            police = 0
        },
        blip = {
            enabled = true,
            sprite = 357,
            color = 38,
        },
        zone = {
            coords = vec3(432.95, -974.71, 21.95),
            size = vec3(31.0, 17.0, 3.0),
            rotation = 90.0
        },
        spawnPoints = {
            vec4(438.21, -988.45, 20.1, 89.73),
            vec4(438.10, -985.48, 20.1, 88.58),
        }
    },
}

label

  • label: string
    • The name shown on the [E] text, the blip and the menu.

jobs

  • jobs: table<string, number>
    • The jobs that can use the garage and the minimum grade for each.
jobs = {
    police = 0, -- every police grade
    bcso = 2    -- bcso grade 2 and up
},

blip

  • blip?: table
    • The garage's map blip. No blip without it.
    • enabled: boolean
      • Show the blip.
    • sprite?: number
      • The blip sprite. Defaults to 357.
    • color?: number
      • Defaults to 0.
    • scale?: number
      • Defaults to 0.8.
    • shortRange?: boolean
      • Only show the blip on the minimap when close. Defaults to true.

zone

  • zone: table
    • The ox_lib box zone players press E in. Turn on Config.Debug to see it.
    • coords: vector3
      • The center of the box.
    • size: vector3
      • Width, length and height.
    • rotation: number
      • The box's heading in degrees.

spawnPoints

  • spawnPoints: vector4[]
    • Where vehicles spawn: vec4(x, y, z, heading). The first point without a vehicle within 2.5 meters is used, in order. When all are taken, nothing spawns.

Vehicle

Every vehicle is a file in its garage's folder, e.g. config/police_ls/tstudio_polcypher.lua. Only label and model are required; generate the rest with /creategaragecar.

Config.JobVehicles['police_ls'] = Config.JobVehicles['police_ls'] or {}

Config.JobVehicles['police_ls']['tstudio_polcypher'] = {
    label = 'Commissioner Cypher',
    model = 'tstudio_polcypher',
}

The first line is the same in every file of the garage. 'police_ls' must match the garage's key in Config.JobGarages.

label

  • label: string
    • The name shown in the vehicle menu.

model

  • model: string
    • The vehicle's spawn code.

access

  • access?: table
    • Which grades can take out the vehicle. Without it, every grade that can use the garage can.
    • minGrade?: number
      • The lowest grade allowed.
    • maxGrade?: number
      • The highest grade allowed.
access = {
    minGrade = 2,
    maxGrade = 4 -- grades 2, 3 and 4
},

plate

  • plate?: table
    • The plate text. Without it, a random plate is used.
    • type: 'job' or 'random'
      • 'job': the prefix and a random number, e.g. POLICE27. 'random': a random plate.
    • prefix?: string
      • Required for type = 'job'.
plate = {
    type = 'job',
    prefix = 'POLICE'
},

appearance

  • appearance?: table
    • How the vehicle looks. Every field is optional.
    • colors?: table
      • primary, secondary, pearlescent and wheel color IDs.
    • plateIndex?: number
      • The plate style, not its text.
    • livery?: table
      • enabled and index. Works with normal liveries and with vehicles that have their livery in mod slot 48.
    • extras?: table<number, boolean>
      • [1] = true turns extra 1 on, false off. Only extras the vehicle has are changed.
    • windowTint?: number
    • wheels?: table
      • type and color.
appearance = {
    colors = { primary = 0, secondary = 0, pearlescent = 0, wheel = 0 },
    plateIndex = 4,
    livery = { enabled = true, index = 0 },
    extras = { [1] = true, [2] = true, [3] = false },
    windowTint = 4,
    wheels = { type = 7, color = 0 }
},

lights

  • lights?: table
    • xenon?: table
      • enabled and color (a xenon color ID).
    • neon?: table
      • enabled, color = { r, g, b } (0-255) and sides = { left, right, front, back }.
lights = {
    xenon = { enabled = true, color = 255 },
    neon = {
        enabled = true,
        color = { r = 0, g = 80, b = 255 },
        sides = { left = true, right = true, front = false, back = false }
    }
},

performance

  • performance?: table
    • engine, brakes, transmission, suspension and armor are mod indexes (-1 = stock). turbo is a boolean.
performance = {
    engine = 3,
    brakes = 2,
    transmission = 2,
    suspension = 0,
    armor = -1,
    turbo = true
},

mods

  • mods?: table<string, number>
    • Cosmetic mods by name, e.g. roof = 0. Only the mods listed are changed, and -1 is stock. The values depend on the vehicle; see Mod Slots.
mods = {
    roof = 0,      -- slot 10 | available: 0-6
    frame = -1,
    lightbar = 1
},

inventory

  • inventory?: table
    • Items put in the vehicle when it spawns. Both inventories are emptied first. Every item name must exist in ox_inventory.
    • glovebox?: { name: string, count: number }[]
    • trunk?: { name: string, count: number }[]
      • Leave it out for vehicles without a trunk, e.g. helicopters.
inventory = {
    glovebox = {
        { name = 'radio', count = 1 }
    },
    trunk = {
        { name = 'medbag', count = 1 },
        { name = 'kegle', count = 10 }
    }
},

Adding a Garage

A new job garage, e.g. for the fire department in Paleto Bay.

Add the garage

Add it to Config.JobGarages in config/jobgarages.lua. The key ('fire_paleto') is the garage's name.

['fire_paleto'] = {
    label = 'Paleto Fire Station',
    jobs = {
        fire = 0
    },
    zone = {
        coords = vec3(-379.5, 6118.6, 31.5),
        size = vec3(20.0, 14.0, 4.0),
        rotation = 45.0
    },
    spawnPoints = {
        vec4(-372.4, 6126.0, 31.4, 45.0),
        vec4(-368.9, 6129.5, 31.4, 45.0),
    }
},

Create its vehicle folder

Create config/fire_paleto/, with the same name as the garage, and add a vehicle to it.

Load the folder

Add the folder to shared_scripts in fxmanifest.lua, before config/jobgarages.lua.

'config/sheriff_sandy/*.lua',
'config/fire_paleto/*.lua',

'config/jobgarages.lua'

Place the zone

Set Config.Debug = true, restart the resource and adjust zone until the box covers the garage. Stand on each parking spot to get the vec4 for spawnPoints.

Adding a Vehicle

The easiest way is to set the vehicle up in game and let /creategaragecar write the config.

Set the vehicle up in game

Make sure the vehicle's resource is started, spawn it and set it up exactly as the job should get it: livery, extras, mods, tint and so on.

Generate the config

Sit in the vehicle and run /creategaragecar. Fill in the label, spawn code, minimum grade and plate prefix. The config is printed in the F8 console.

Create the vehicle file

Create a file in the garage's folder, e.g. config/police_ls/tstudio_polcypher.lua, with the registration lines, and paste the generated fields inside:

Config.JobVehicles['police_ls'] = Config.JobVehicles['police_ls'] or {}

Config.JobVehicles['police_ls']['tstudio_polcypher'] = {
    label = 'Commissioner Cypher',
    model = 'tstudio_polcypher',
    -- the generated configuration...
}

Don't wrap the generated fields in another return { ... }.

Add starter items

Add inventory if the vehicle should come with items in the glovebox or trunk.

Restart and test

Restart lc_jobgarages and take the vehicle out of the garage.

A minimal vehicle

A vehicle without anything special only needs a label and a model:

Config.JobVehicles['police_ls'] = Config.JobVehicles['police_ls'] or {}

Config.JobVehicles['police_ls']['tstudio_polscorcher'] = {
    label = 'Police Bike',
    model = 'tstudio_polscorcher'
}

mods uses readable names instead of GTA's mod slot numbers. Which values a slot has depends on the vehicle: /creategaragecar writes the range next to each mod, e.g. roof = 0, -- slot 10 | available: 0-6. -1 is stock.

Slots without a name

Addon vehicles can use other slots. /creategaragecar scans slots 0 to 49 and writes unknown ones as mod<slot>:

mod17 = 0, -- slot 17 | available: 0-2

Set them in the right place

Engine, brakes, transmission, suspension, armor and turbo belong in performance, the livery in appearance.livery. Don't set them in mods as well.

Commands

/creategaragecar

Writes the config for the vehicle you sit in: label, model, access, plate, appearance, lights, performance and every mod it finds, with the available values for each. It prints the config in the F8 console; it doesn't change any files or spawn anything.

/creategaragecar
  • You must sit in a vehicle.
  • A dialog asks for the label, the spawn code, the minimum grade and the plate prefix.
  • Copy the output from F8 into a vehicle file, see Adding a Vehicle.

Every player can run it, but it only reads their own vehicle and prints to their own console.
